## 対応済み

- **Ctrl-\（SIGQUIT）で一時コピーが残る問題を修正**（2026-09-16）。
  `InstallCleanupOnSignal` が SIGINT/SIGTERM/SIGHUP しか捕まえておらず、Ctrl-\ で
  復号済みの d cookie を含むコピーが `$TMPDIR` に残っていた（敵対的レビューが実測、こちらでも再現）。
  SIGQUIT を追加し、`internal/auth/signal_cleanup_test.go` が**実際にシグナルを撃って** 4 種すべてを固定。
  代償として Go 既定の SIGQUIT（goroutine ダンプ）は出なくなる。
  - [ ] **実バイナリでの確認は未実施**: `./slack channels` の実行中に Ctrl-\ を押し、
        `$TMPDIR/slack-cli-extract/` が空のままであること（テストはパッケージ内の子プロセスで確認）

- **③（起動時の掃除）が検証を通らずに削除していた問題を修正**（2026-09-16、P1）。
  `SweepStaleTempDirs` が `ensureTempRoot` の symlink / 所有者検証を通らず
  `os.ReadDir` → `os.RemoveAll` していたため、`$TMPDIR/slack-cli-extract` を
  シンボリックリンクにされると**リンク先を再帰削除**できた（レビュー 2 本が独立に指摘、こちらでも再現）。
  検証を「削除する側」へ移し（`openVerifiedTempRoot`）、走査・削除を
  ディレクトリ fd 起点（`os.Root`）にしてパスの再解決を無くした。
  あわせて削除失敗を無音にせず stderr へ出すようにした。
- **③ が「起動時」に走っていなかった問題を修正**（2026-09-16、P1）。
  呼び出しが資格情報を読む経路（`extractCookies` / `ExtractTokens` / `DiscoverWorkspaces`）
  にしか無く、`slack help` / `slack config` では残骸が残ったままだった。
  `cmd/slack/main.go` の先頭 1 箇所へ移し、AST テストで配線を固定。
  実バイナリで A/B 確認済み（`slack help` 実行後に残骸 0 件）。
- **`pidFromTempDirName` が `+1` / `007` / 前置ゼロを受けていた問題を修正**（掃除の母集合を広げない）。

- **敵対的レビュー 2 周目（修正差分そのものへの攻撃）で出た指摘に対応**（2026-09-16）。
  1 周目の修正で新設した防御が、実は検証を素通りしていた:
  - `os.Root` は「ルート内に留まる**相対**シンボリックリンクは追う」（絶対リンクだけ拒否）。
    1 周目のテストは絶対リンクしか使っておらず、**検証を全部消しても緑**だった。
    相対リンクのケースを足し、Lstat した実体と開いた実体の同一性（`os.SameFile`）も見るようにした。
  - ①②（defer / シグナル経路）が `os.RemoveAll(パス文字列)` のままで、③と同じ穴が残っていた。
    検証済み root の fd 経由（`r.RemoveAll`）に統一し、削除ループはロックを保持したまま回すようにした
    （先に map を空にしてロックを外すと、シグナル経路が「消すものは無い」と判断して削除途中で終了する）。
  - **作業領域を `$TMPDIR` から `~/Library/Caches/slack-cli/extract` へ移した**。
    `$TMPDIR` は呼び出し側が動かせるため、掃除が一時領域でない場所（`$HOME` 等）を消しに行けた
    （`slack help` で再現）。未設定時の `/tmp` は誰でも書けるので、別ユーザーが同名の
    シンボリックリンクで居座ると資格情報の読み取りが恒久的に壊れる、という問題もあった。
  - シグナル受信直後に `signal.Reset` するようにした。後始末が長引いている間、
    **どのシグナルでも止められなくなる**（Ctrl-C 連打も SIGQUIT も効かない）状態だった。
    これで「1 発目 = 後始末して終了 / 2 発目 = OS 既定で即死（goroutine ダンプも出る）」になる。
  - `TestCleanupIsWiredInMain` が「main のどこかで呼ばれている」しか見ておらず、
    呼び出しを末尾へ動かす退行（`slack help` で走らなくなる）を検出できなかった → 位置まで固定した。

- **敵対的レビュー 3 周目の指摘に対応**（2026-09-16）。
  2 周目の修正にも穴が残っていた:
  - **①（defer）だけが検証も fd も通らないままだった**（②③だけ直していた）。①の窓は
    「一時ディレクトリを作ってから defer が走るまで」＝作業中ずっとなので構造的に最も広い。
    削除の実装を `removeVerified` 1 本に寄せ、①②③すべてがそこを通るようにした。
  - **検証が最後の 1 コンポーネントにしか掛かっていなかった**。`~/Library/Caches/slack-cli`
    （親）を symlink に差し替えれば、検証済み root ごと任意の場所へ移せた。
    `os.UserCacheDir()` を起点に 1 コンポーネントずつ降りる形にした。
  - **「環境変数で動かない」は誤りだった**（`os.UserCacheDir` は HOME 基準なので HOME で動く。
    darwin では `$XDG_CACHE_HOME` を見ない）。コメントを実装に合わせ、相対パスの HOME を拒否した。
    $TMPDIR を捨てた根拠は「/tmp は誰でも書けるので別ユーザーが居座れる」だけが残る。
  - **残骸の寿命が $TMPDIR 時代より長くなっていた**（`/var/folders` は OS が 3 日で回収するが、
    `~/Library/Caches` にはそれに相当する仕組みが見つからない）。7 日より古いものは
    pid の生死に関わらず回収するようにした（pid 番号の再利用で永久に残る問題も同時に解消）。
  - `signal_cleanup_test.go` が **HOME を隔離しておらず実 `~/Library/Caches` にコピーを作っていた**。
  - `TestProcessAliveGuardsNonPositivePID` の fixture が弱く、ガードを外しても緑だった。

### 自動テストを入れたもの（2026-09-19、seam 経由）

3 周の敵対的レビューで「無検査」と指摘され続けた 3 つは、**実環境では決定論的に
条件を作れない**（別アカウント / 実時間のレース / 壁時計）。production に最小の seam を
置いて検査できる形にした。seam は**守りたい窓の内側**に置いてある（窓の手前にしか
割り込めない seam では、変異が全部緑で通る）。

- [x] **所有者（uid）検査** — `currentUID` を差し替えて「自分以外の所有」を作る。
      `TestForeignOwnerIsRejected` / `TestOwnerCheckFailsClosed`
- [x] **`os.SameFile` による差し替え検出** — `afterLstatHook`（Lstat と OpenRoot の間）で
      同じ名前に別 inode のディレクトリを置く。`TestSwapDuringVerificationIsDetected`
- [x] **`signal.Reset` の順序** — `handleCleanupSignal` に依存を注入し、
      「既定へ戻す → 後始末 → 終了」の順序を検査。`TestSignalHandlerResetsBeforeCleanup`

いずれも対応する変異（検査を外す / 順序を逆にする）で red を確認済み（全 44 件）。

### 残っている限界（テストでは埋まらない）

- [ ] **`signal.Reset` の OS 上の効果**: 順序は検査したが、「2 発目で実際に止まる」ことは
      壁時計に依存するため未検証。🚨 3 周目の実測で、**バックグラウンド起動（`&` / cron / CI）
      では SIGINT が SIG_IGN で継承されるため 2 発目が効かない**ことが分かっている。
      端末から起動した場合のみ成立する（コードにもその但し書きを書いてある）。
