# 003 retro: 3 CLI（slack / esa / nrql）のリーク・バグレビューと修正（2026-09-28）

起票日: 2026-09-28

slack-cli / esa-cli / newrelic-nrql-cli を並行でレビュー → 修正 → 敵対レビュー（各 repo 2〜3 周）→
commit & push したセッションの振り返り。3 repo は同じ Chrome Cookie 復号・プロファイル走査を
移植で共有している。各項目の切り出し先は案で、**実行はユーザーの判断を待つ**。

## 何が起きたか（数）

- 最初のレビューで採用した指摘: slack 7 / esa 9 / nrql 6。リソースリークは slack の後始末の 2 件
  （シグナル受信〜終了の間に作られた Cookie DB / leveldb の一時コピーが残る、削除に失敗したパスを
  同じプロセス内で再試行しない）。残りは「黙って欠ける・誤案内する」形のバグ
- 敵対レビュー: 各 repo 2〜3 周、計 11 本（1 周目 6・2 周目 3・3 周目 2）。**「自分の修正」が HEAD より
  悪化させた退行を 10 件超**検出
- 実機で再現した旧不具合: `slack history -n 1500` が 100 件 rc=0（limit>1000 を黙って既定値へ）

## 1. 私の指示の前提が誤っていて、3 repo に同じ退行を配った（最大の学び）

「EACCES / EPERM はフルディスクアクセス不足 = どのプロファイルでも同じ → 即停止」と、
esa・nrql の実装者へ**同じ前提のまま**指示した。chmod 000 や root 所有のプロファイルは
プロファイル固有で、1 個壊れているだけで自動検出全体が止まる（HEAD は continue で動いていた）。
slack の敵対レビューがテストで再現して初めて気づき、3 repo へ訂正を送り直した。

その後も同じ形が 2 回出た: 「壊れた DB は止める」（esa/nrql）、「-profile 明示時は未認証なら拒否」（esa）。
3 回とも共通して、**fail-closed に倒す分類を足すとき、「1 個体だけ壊れた状態」で全体が止まる形を
試していない**。

切り出し先案: `_claude/rules/adversarial-review-own-safeguards.md` §1 の「環境を変えた実験」の表に 1 行追加
（作る条件「複数の候補のうち 1 個体だけ壊れている」/ 確かめること「全体が止まらないか」）。本文の要旨:
「**複数の候補を順に試す処理で、失敗を『即停止』に分類するときは、その失敗が本当に全候補で同じかを
1 個体だけ壊した fixture で確かめる。**止めるのは候補を変えても直らないもの（鍵・ネットワーク・
レート制限）だけにし、個体固有のものは記録して次へ進み、全滅時に理由を添える」。

## 2. 移植で共有しているコードの指摘が、repo ごとに独立に再発見された

復号の全件失敗・WAL 読み取り失敗・権限の分類・LimitReader の切り詰めは、3 repo でほぼ同じコード。
repo ごとにレビュアーを立てたので、同じ穴を 2〜3 回見つけ、そのたびに他 repo へ手で横展開した
（SHA256(host_key) 照合も nrql で見つけて esa / slack へ送った）。

切り出し先案: `_claude/rules/parallel-write-agents-need-worktree-isolation.md` の「各作業が変える判断を
1 行ずつ書く」の項へ追記「**移植元・移植先のように同じ判断を複数 repo が持つなら、レビューは共有部分を
1 本で見て全 repo へ配る。**repo ごとに立てると同じ指摘の再発見と横展開の手作業が repo の数だけ増える」。
なお、この共有部分は別セッション（slack-cli-17）が `dotfiles/src/chromecookie` へ切り出し中で、
構造的にはそちらで解消する。

## 3. サブエージェントが書いた「外部仕様の根拠」が未測定のままコードコメントに入った

- esa: 「host-only Cookie の host_key は小文字なので大文字の team では認証が通らない」→ 実 DB を
  1 コマンド（`SELECT DISTINCT host_key …`）で見たら `.esa.io`（ドメイン Cookie）で誤り
- nrql: 「-format json を SELECT の並び順にする」→ 実 NR は数値列をアルファベット順で返すので、
  修正の効果は「TSV と揃う」まで。help の文言も誤っていた

却下: 新しい提案にはしない。`measure-external-cli-streams-separately.md`（外部ソースは仮説、手元の実験を 1 本通す）と
`subagent-model-tiering.md`「検閲の観点」（根拠のない断定の混入は裏取りする）が既にカバーしている。今回は適用漏れで、
どちらも実機で 1 回叩いた時点で見つかった。
