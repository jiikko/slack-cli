# 007 (feat): チャンネル一覧（conversations.list）の結果をしばらくキャッシュする

起票日: 2026-10-07

## 概要

大きなワークスペースでは `conversations.list` の全件取得が重い（ubiregi は約 3500 チャンネルで、1 回の取得に約 18 リクエスト。
`conversations.list` の制限は 1 分あたり 20 回前後で、数分のうちに 2 回取ると 429 になる。issue 006 の「現状」節の実測）。
チャンネルの一覧はそう頻繁に変わらないので、取得した結果をしばらく手元に置き、次の実行ではそれを使う。

006（429 を受けたら待って続きを取る）とは直すものが違う。006 は「1 回の取得を最後まで終わらせる」、本 issue は「取りに行く回数を減らす」。

## 使う場所

- `slack channels`: 全件をキャッシュし、`-types` / `-name` の絞り込みは手元で行う
- チャンネル名 → ID の解決（`ResolveChannel`。`slack history '#name'` / `slack thread '#name' …`）: キャッシュに名前があればそれを使う。
  無ければ今どおり API を 1 ページずつ探す（キャッシュの後に作られたチャンネルを「無い」と誤らない）

## 対応方針（案。着手前に決める）

- 置き場所: `~/Library/Caches/slack-cli/<workspace>/channels.json`（workspace ごと。ディレクトリ 0700・ファイル 0600）。
  書き込みは一時ファイル + rename（途中で落ちても壊れたキャッシュを残さない）
- 有効期限: 既定 1 時間（推奨。設定で変えられるようにするかは要検討）
- `-refresh` でキャッシュを使わずに取り直し、結果でキャッシュを更新する
- 途中で失敗した結果（`PartialError`）と、上限で打ち切られた結果（`TruncatedError`）は保存しない（不完全な一覧を「全件」として使い回さない）
- キャッシュを使ったときは stderr に 1 行出す（いつ取得したものか。stdout には出さない）
- 🚨 プライベートチャンネルの名前がディスクに残る。資格情報（cookie / トークン）ではないが、README「安全のための制約」の
  「資格情報を残さない」と並べて、何を残すかを書く。cookie / トークンはキャッシュに入れない（今の `WriteProfileCache` と同じ方針）
- キャッシュを読めない・壊れているときは使わずに API から取り直す（キャッシュはあくまで速くするための補助の経路で、正しさをそれに預けない）

## 決めること

- 有効期限の既定値（推奨 1 時間）
- `users.list`（`slack users`）も同じ仕組みでキャッシュするか
